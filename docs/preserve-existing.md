# 保留现有 SSH 与 RustDesk 接入（0.4.0a33 候选）

适用于已有 Windows OpenSSH 和 RustDesk 服务、希望加入 GMSSH 而保留原环境的电脑。没有既有服务的新电脑继续使用原专用账号安装方式。已在独立 Windows 测试机完成保留模式安装、备份升级、主要 CLI/MCP 检查、锁屏拒绝、解锁与正常重启后的服务和原客户端恢复。后台焦点限制及重启后的测试记事本输入复核另见[验证记录](validation.md)。

## 安装流程

1. 完整运行候选安装包。检测到既有 SSH 时，安装器提示「保留现有服务」，确认后只读检查原配置、签名、监听进程及主机公钥。
2. 本模式要求原连接账号已是本地管理员，两个服务均已运行并自动启动；SSH 使用一个明确端口、允许账号密码认证、SFTP 和通往 `127.0.0.1:21118` 的本机转发。原 SSH 配置可采用标准默认位置或带引号的 `-f` 配置参数。自定义端口保留，不固定为 22。
3. 不满足条件时提示原因并停止，不自动放宽原认证、修改配置或重启原服务。该检查不证明某个账号已获原 SSH 的 AllowUsers/Match 许可，仍需控制端实际认证和传输验证。
4. 只新增 GMSSH 程序与数据、原用户的托盘登录任务、本程序的 SYSTEM 接入任务及 TCP 22257 局域网规则。已有 SSH/RustDesk 的密码、主机密钥、启动参数、自启和防火墙规则保持原样；不重装它们或 VC++ 运行库。
5. 输入既有 Windows 账号密码（不是 PIN）和既有 RustDesk 固定连接密码，两者可以不同。先验证 Windows 账号，再通过原桌面服务的正常只读握手验证桌面密码及电脑名，两项都通过才保存。密码错误、超时、额外认证或设备不符时不覆盖已有凭据、不刷新连接码。密码以 Windows DPAPI 加密，保存在受限的本机凭据文件内，不写进公开连接信息、日志或二维码。
6. 在托盘点击「创建接入授权」，按需选择查看、输入、文件或终端等通道，创建并复制授权码。在管理端加号 →「添加机器」→「Windows」粘贴，或在 AI 接入面板启用。

独立桌面通道由服务端使用保存的桌面密码认证，不把该密码发给管理端。托盘也保留普通配置及「SSH 接入码」入口；后者只用于 SSH，桌面需要管理端单独认证。

## 后续管理

- 「更新接入凭据」重新验证并保存既有密码，不修改 Windows 或 RustDesk 密码；外部改密后使用此入口更新。成功时刷新原 SSH 接入码，既有独立授权保留；验证失败时保留原凭据和码，并区分 Windows 账号失败、桌面密码错误和桌面认证未确认。
- 验证和保存期间显示进度并临时禁用重复入口；完成后明确提示成功、失败或取消。若密码已经保存但接入任务未恢复，单独提示服务恢复问题，避免把它误报为密码错误或让用户重复提交。
- 「暂停 GMSSH 接入」仅停止本程序的接入任务；原 SSH、RustDesk 和通过它们建立的外部连接继续由原程序管理。
- 升级只备份/更新 GMSSH 自身文件及任务。原服务、端口、主机公钥或账号 SID 变化时停止升级，要求管理员重新核对。
- 局域网 IPv4/IPv6 沿用既有网络条件。保留模式不代管原 SSH 的跨网段 IPv6 防火墙规则。

终端使用连接账号的 Windows 令牌；当前独立文件通道由 SYSTEM 服务处理，不是普通账号的文件权限沙箱。因此本模式要求既有管理员账号，并持续核对 SID 和管理员组成员资格；普通账号被拒绝而不会自动加组。独立授权仍按通道限制能力，也不绕过其他用户文件的加密。
