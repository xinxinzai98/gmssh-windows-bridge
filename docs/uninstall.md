# 卸载与重装（0.4.0a34 候选）

Windows 设置 → 应用 → 已安装的应用 → **GMSSH Windows → 卸载**。托盘的“卸载 GMSSH（系统设置）”也会打开这一位置。卸载窗口先列出实际程序文件、任务、防火墙规则和保留内容，点击“备份并卸载”后才执行；取消不修改安装。

## 卸载范围

- 停止并移除 GMSSH 托盘和接入任务，移除经归属校验的 GMSSH 规则和“已安装的应用”入口。
- 程序目录移入本机可恢复备份，连接配置、独立授权及受保护凭据留在原数据目录。
- 若桌面引擎是 GMSSH 自己安装、服务路径也与记录一致，移除该内部桌面服务。保留模式不会停止或卸载用户原有的 RustDesk。
- 专用 `gmssh` 账号只有在名称、SID 和安装记录均匹配时才停用，保留账号及文件以供恢复。原有 Windows 账号、密码、用户目录和 SSH 服务不改动；系统 OpenSSH 组件保留，其他用途的规则保留。

检测到未知文件、重解析点、变更的账号身份或同名但不属于本安装的资源时停止。停止任务、移除规则或移动目录失败时尝试恢复原安装，并明确报告恢复结果和备份位置；不把部分完成提示为成功。

## 重新安装

再次运行完整安装包，会识别保留的卸载记录，显示“重新安装”。确认后校验备份并恢复原配置，再应用安装包中的当前程序版本。无需重设原 Windows / RustDesk 密码或重新创建连接账号，原设备身份和独立授权保留。

备份缺失、被修改或出现同名资源时停止，不覆盖新资源。恢复失败会尽量回到卸载状态，并保留原备份与失败副本。正常卸载不会删除系统 OpenSSH、其他远控软件、用户文档或私有连接数据；这也不是“清空此电脑全部远控配置”的入口。

需要只读核对实际清单时，可在管理员 PowerShell 运行：

```powershell
& "$env:ProgramFiles\GMSSHWindowsBridge\uninstall-windows.ps1" -Preview
```

备份及恢复记录位于 `%ProgramData%\GMSSHWindowsBridge\backups\uninstall-…`。其中可能包含设备身份与授权记录，应保留在原电脑，并按连接配置保护，不纳入公开发布包。

已在保留现有 SSH/RustDesk 的实体测试机完成实际“备份升级 → 卸载 → 重装恢复”：原服务及进程、账号密码、主机密钥、加密凭据和独立授权保留；管理端重开恢复桌面，CLI/MCP 接入通过。专用账号和内部引擎分支目前由真实 Windows 5.1 上的合成事务回归覆盖，不能与实际移除原服务混为一谈。详细范围见[验证记录](validation.md)。
