# Windows 解锁（本地候选）

在 GMSSH 的 Windows 桌面右上角“更多选项 → Windows 解锁”中设置。这里有两份相互独立的凭据：

| 凭据 | 用途 |
| --- | --- |
| GMSSH 连接密码或独立授权 | 接通监控、桌面和已获准的工具 |
| Windows 账户密码 | 登录或解锁 Windows 当前所选账户；不修改该账户密码 |

“允许自动解锁”默认关闭。在 Mac 管理端连接桌面后，填写原 Windows 账户密码，勾选此项并点“保存设置”。Windows 密码单独保存在此 Mac 钥匙串，按已核验的设备身份区分，不使用连接密码作为默认值。每次新打开桌面标签最多自动提交一次；自动重连、失败和新视频帧不会触发反复尝试。

关闭此项并保存会移除单独保存的 Windows 密码，保留 GMSSH 的连接凭据。也可不保存，填写 Windows 密码后点“解锁一次”；关闭窗口或提交后清空输入框。保存与发送都不代表 Windows 登录已成功，需要核对远端画面。

0.4.0a34 管理端会在提交后通过既有交互工作者只读核对结果，确认后显示“Windows 当前已解锁”。尚在锁屏或系统安全确认界面、接入授权失效以及未能确认结果会分别提示；不会因此自动重试密码。查询不读取 Windows 登录密码，也不把状态未知误报为密码错误。旧连接不支持核对时仍需查看远端画面。

系统需选用“密码”登录方式。独立授权通道先查询 Windows 的实时控制台会话，仅在确认锁屏或尚未登录时激活登录画面，短暂等待后再次确认仍为同一锁定会话，才发送解锁消息；已解锁时不点击、不发送密码，状态未知时停止。首次登录前的 `Connected` 会话只在没有登录用户时被识别为登录界面，不放行已登录或断开的会话。

PIN、指纹、Windows Hello、切换用户及选择密码登录方式仍由正常 Windows 界面处理；必要时可点“唤起登录界面”发送 Ctrl + Alt + Delete。此候选不自动选择账户、切换认证方式或更改 Windows 自动登录策略。自动解锁后若系统登录切换关闭了原桌面连接，管理端只在 30 秒内额外恢复一次已保存的桌面连接，不重新发送 Windows 密码；认证失败、主动断开、关闭页面或存在未提交密码时不重连。

安全协议需要远端 Windows 桌面引擎 **1.5.1 或更新版本**。独立授权连接还要求 GMSSH 服务端明确声明 `windowsUnlock: 1`；旧服务端不转发新消息，管理端会停止解锁而保留正常桌面。使用 [RustDesk 上游新增的 OSLogin 消息](https://github.com/rustdesk/rustdesk/pull/16520)，在桌面连接已经验证、且允许键盘控制后提交，由远端在输入前检查登录或锁屏状态。旧版和未知版本只提供兼容提示，密码不会回退成普通文本按键。由远端检查到输入仍存在很短的时间间隔，不把它描述为 Windows 登录事务。

这项凭据不进入连接码、二维码或当前配置备份，也没有加入 CLI/MCP 或扩大已有 AI 授权。锁屏期间，AI 桌面观察、截图和输入仍按原规则拒绝。

本地构建、协议/权限/存储回归及浏览器布局检查已通过。2026-10-20 已在获得授权的实体测试机备份升级桌面引擎到官方签名的 `1.5.1+68`，切换独立 Mac 验收客户端，并确认原 SSH、接入任务和现有 AI 授权可用。该版本来自上游 nightly 的固定构建，不代表稳定版安装包已经支持此功能。

实机在正常窗口分别更新既有 Windows 账号与 RustDesk 连接凭据后，已通过真实桌面认证，Mac 客户端正常重开也恢复了桌面连接。Windows 解锁选项已在正常设置面板启用，独立密码保存到此 Mac 钥匙串；锁屏后 AI 观察、截图和输入均已实测被拒绝。锁屏后正常重开 Mac 客户端已自动恢复解锁；最终组件正常重启后，打开 Mac 客户端即自动登录 Windows、恢复画面与原用户托盘，同一 MCP 客户端也恢复 `OK`，没有再次输入密码或重新授权。开机程序的 UAC 安全桌面仍会使 AI 工具返回 `DESKTOP_LOCKED`，不会自动接受提权请求。完整结果与限制见[验证记录](validation.md)。
