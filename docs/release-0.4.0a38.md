# 0.4.0a38 稳定收尾候选

状态：Alpha 源码修复候选，公开安装包尚未发布。基于 0.4.0a37，保留原产品范围，代码构建阶段不新增功能、不部署设备；随后单独授权的临时只读复测、无线协议对照及监控修复见下节。安装步骤见[安装与接入](getting-started.md)，原有能力及边界见[0.4.0a37 说明](release-0.4.0a37.md)。

## 修复内容

- 桌面二进制消息异步读取结束后，再次核对连接代数。旧连接的延迟消息不会更新新连接的诊断，也不会向替代连接发送旧消息的回应。
- 发送登录信封前核对连接代数及套接字打开状态，忽略已断开或已替换套接字的迟到打开事件。
- 视频解码失败沿用同一会话的失败处理，正确结束连接历史与状态，只报告一次失败；旧解码器回调不会影响替代会话。

三个本地回归使用真实协议编码/解析和合成传输、解码器，先在旧代码复现失败，再验证修复。正常当前连接的消息仍可处理。上述结果不等同于新的 Windows 设备验收，也不将这三个边界认定为此前 Wi-Fi 长超时的根因。

## 临时只读复测

在既有 Wi-Fi 测试机上使用独立安装的本版组件和临时浏览器查看器，沿用原有授权与固定证书，并将输入、剪贴板、文件、终端、电源及 Windows 解锁全部关闭。约 11 分钟观察窗口内出现 4 次自然的 20 秒 HTTPS 读取超时，未注入故障、输入凭据或手动重连。

程序依次执行最多 3 次自动重连；第二次重连后的真实桌面已观察确认，最后一次尝试随后又超时，界面正确显示“自动重连已停止”。超时时记录到未确认的发送数据和 TCP 重传，当时尚不能确定具体故障位置。**初轮连续连接验收未通过，不能将本候选标为稳定正式版。**

测试结束关闭临时标签、进程和本机监听，清除临时本地令牌文件。未替换日常 Mac 应用、安装 Windows 程序、修改设备设置或操作另一台保留设备。此项是临时浏览器查看器实测，不替代原生 Mac 应用重新验收。

## 后续 Wi-Fi 协议对照

后续获得针对同一测试机的明确网络变更授权，在原 Wi-Fi、相同接入点和信道上完成 ac → ax → ac 对照。两次 ac 的四分钟公共 HTTPS 探测分别为 174/174、204/204 成功，桌面均未超时；恢复 ax 后约 64 秒重现 20 秒超时。临时关闭 MuMu、VMware 绑定仍有故障，已恢复全部原绑定。该结果支持这台电脑、当前驱动与 AP 的 ax 链路兼容性问题，尚未细分到硬件、驱动或 AP 固件的内部缺陷。

按“对照通过才保留”的授权保留该机 ac 设置后，同一临时只读桌面会话继续观察 **20 分 30 秒，7949 次响应成功，零超时、零重连**；从该会话建立起共约 26 分 19 秒。同期补充四分钟公共 HTTPS 探测 185/185 成功。结束前确认真实画面，回读相同接入点、原服务进程、原 14 项绑定，以及临时任务和采集器清理；随后关闭本轮查看器及回环监听，清除临时令牌，保留原授权和凭据。

该机协商速率从 573.5 降为 400 Mbps，不等同实际文件吞吐率。这是经授权的单机兼容设置，程序不会自动关闭其他设备的 ax；没有增大产品超时、添加无限重试、部署 Windows 新程序或替换日常 Mac 应用。临时查看器的通过结果不代替原生客户端、其他设备和纯净首装验收。完整脱敏对照见[验证记录](validation.md)。

## 后续原生 Mac 客户端验收

收到同一测试机的原生客户端验收指令后，备份并将 Mac 专用验收端更新至 0.4.0a38。核对 124 个运行包文件、实际提供的前端资源及应用签名，保留配置、钥匙串、原应用标识和主可执行文件 UUID；本轮未修改 Windows 程序或设置。

- 从实际画面起，前台观察 631.533 秒，文件中心后台观察 606.377 秒，始终是同一个桌面会话，零自然桌面失败、零替代会话；返回后实际画面与远端时钟正常。
- 从文件中心通过应用菜单正常退出，主程序和三个本机桥端口全部关闭，旧会话以 `WINDOW_CLOSED` 正常结束。正常重开同一路径应用后，自动恢复选中的桌面、新会话及真实画面，无密码、连接按钮或导航操作。
- 重开后继续观察 751.953 秒，包含 305.285 秒前台、326.695 秒文件中心后台；返回后真实桌面正常，仍为同一新会话。预期的正常退出单独记录，全程没有自然桌面失败或额外重连。

观察中曾有一次后台监控采样失败标记，下轮刷新自行恢复，桌面会话未受影响；仅凭标记尚不能定位内部原因，不写成所有监控请求均成功。文件中心只读列出磁盘，原完成任务保留，没有启动新传输。结束后停止本轮观察脚本，将原生客户端留在已连接桌面；另一台保留设备未操作。上述通过限定于该机当前兼容设置和既有安装，不替代其他设备、纯净首装及未逐项覆盖工具的验收。

## 后续监控采样修复

沿同一调用链在该 Wi-Fi 测试机复现：快慢指标与设备详情共用两个信息查询槽位，旧服务端在槽位占满时立即返回 HTTP 409。20 次详情读取中有 3 次在 0.18–0.72 秒内失败；单独控制的三轮并发查询也重现拒绝。原页面没有保存那次历史标记的原因码，因此不能逐条追溯旧请求，但此问题已有旧代码回归与现场对照。

修复使采集在原六秒总预算内等待空位，仍最多同时执行两个查询；等待期间释放注册表锁，桌面和授权请求可以继续处理。没有增加产品超时、重复执行查询或自动修改设备网络。Mac 页面保留白名单原因码、连接/授权/查询阶段和耗时，失败时标明保留上次数据；超时后的迟到回调不再发送请求或覆盖结果。

按修复及验收指令，备份后更新同一测试机的接入程序和摘要文件，并更新 Mac 专用客户端的两个采集页面文件。原 SSH/RustDesk、账号密码、主机密钥、加密凭据、独立授权、防火墙与网络设置均核对保留；没有重新部署包内无关的 IPv6 脚本差异。修复后相同 20 次串行读取全部成功，三轮三查询并发及三个串行控制也全部成功。原生页面观察 10 分 19.533 秒，32 次观察记录中未见采集异常，取得 18 个不同成功采样时间；文件中心后台及返回桌面正常，同一桌面会话保持约 12 分钟。具体本地检查和证据边界见[验证记录](validation.md)。
