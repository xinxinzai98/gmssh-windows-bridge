# 独立文件中心

0.4.0a23 开发分支候选。Windows 与 Linux 共用主进程恢复队列；支持流式传输、目录操作、常用目录和重开恢复，不要求先建立桌面画面。已有 Windows SSH 与 Linux SFTP 不要求升级 Windows 服务端；新独立授权需使用新版服务端。

## 使用方式

- 点击设备卡片、列表或详情中的“文件互传”，或顶部“文件中心”。各设备保留目录位置，“全部任务”显示跨设备任务，包括重开后尚未打开文件页的任务。
- 上传通过系统文件选择窗口授予读取权限。拖入文件或文件夹时，再在系统窗口确认同一批源文件；网页不提交本机路径，也不缓存整份文件。
- 单文件下载选择保存位置；多文件或文件夹下载选择本机目录，逐文件保存并保留目录结构、中文名称和空目录。新版中心的文件夹下载不再先打包 ZIP。
- 任务可以暂停、继续或取消。上传同名冲突可改名继续；已有完整文件不会被自动覆盖。完成表示校验通过并已提交本机或远端文件。
- 收起文件中心、回首页、切换设备、重新载入文件页或关闭桌面标签，均不会停止主进程任务。退出时默认继续传输；选择“暂停并退出”会先保存任务，再关闭后台连接。

Linux 继续使用 GMSSH 原生文件管理。其任务暂未纳入本中心的统一恢复队列。旧管理页面和桌面文件侧栏仍提供原浏览器兼容路径，保留 512 MiB 与 ZIP 限制，退出后需要重新选择文件。

## 目录浏览与选择

“搜索当前目录”按文件名筛选已经载入的目录项，支持中文和不区分大小写；不递归搜索子目录。可按名称自然顺序、大文件优先或最近修改优先排序，文件夹始终在前。大小和修改时间显示在文件旁，缺少时间时显示“时间未知”。“刷新”重新读取当前目录；搜索和排序本身不会重复查询远端。

“全选”只选择当前筛选结果，再次取消也只影响这些可见项。切换筛选保留其他已选文件，并明确提示其中多少项被隐藏；“下载所选”按显示的选择总数处理。“清空选择”清除本目录的全部选择。同目录刷新会更新所选项的大小等信息，消失或类型变化的项目会移出选择。

打开新目录期间暂停旧目录的上传和下载操作。读取成功后清除旧目录的搜索与选择；失败时恢复上次成功的路径并显示原因，不把旧列表标成新目录。较早请求的返回不会覆盖后来的导航。矮窗口内目录控制区可滚动，文件列表保留可操作高度。

每个目录仍只载入最多 2000 项；达到上限时明确说明搜索未覆盖未载入的文件。此限制没有因新增搜索而扩大。

## 目录历史与新建文件夹

路径栏的后退/前进按钮按当前设备分别维护最近 64 项成功读取的目录。返回时恢复该目录的搜索词、排序和滚动位置；失败导航不加入历史，同目录刷新不清除前进分支，后退后打开其他目录会建立新分支。历史只在该设备文件页内存中保留，不保存到设备备份，也不会恢复旧的下载选择。

打开实际磁盘或文件夹后，可点击“新建文件夹”。编辑区显示固定的父目录，只接受一个有效的文件夹名称；不接受路径、保留名称或超长目标。提交期间锁定目录导航和旧目标的传输按钮，避免改变正在操作的位置。

创建沿用已有认证文件通道。后端确认目标路径及结果后，显示“已创建”或“已存在，未改动”，并刷新父目录；同名普通文件不会被覆盖。若权限、连接或响应异常，保留名称并提示刷新目录核对，不自动重试或假报创建成功。取消只关闭编辑区。此功能没有引入重命名、删除或目录清空操作。

## 常用目录收藏

进入常用文件夹后点击“收藏目录”，在“常用目录”中查看完整路径并打开。每台设备最多 12 项，收藏保存在这台管理端本机，重开后仍可找到；只加载列表时不自动访问远端或本机文件。点击打开前通过现有认证通道核对保存的 SSH 主机指纹，再读取该目录。

设备身份、连接或目录已经变化时保留原收藏并说明原因，不自动换到其他位置。若身份核对期间已经手动导航，则不会用较早的收藏请求抢占新位置。“移除”只删除本机收藏记录，不删除任何目录。多个窗口通过同一个管理进程保存，列表在展开或操作时更新，不新增定时远端轮询。

记录位于本机文件任务目录的 `file-places.json`，与传输记录分开保存，使用私有目录、文件权限和原子替换；只含设备 ID、SSH 指纹、路径及显示名称，不含连接密码、私钥或文件内容。收藏不是文件授权，不进入设备配置备份或公开发布包。记录损坏时保留原文件，文件传输仍可使用。

旧版管理进程未提供收藏能力时保留原文件界面；旧浏览器兼容侧栏和 Linux 原生文件工具不共用此收藏记录。

## 任务管理

“全部任务”可按设备、状态以及文件名或路径筛选；单设备传输页也支持状态与名称/路径搜索。先显示 50 项，点击“再显示”可继续查看当前筛选中的任务；主进程最多 2000 项，不再只展示前 100/200 项。轮询更新进度时保留搜索焦点和已经展开的详情。

任务详情显示来源、目标、创建时间、状态代码及完成后的 SHA-256。失败原因与恢复提示同时展示，兼容保存仍有独立阶段和进度；路径与摘要仅在本机任务界面可见，不进入设备配置备份。读取任务详情不会自动读取对应文件或授予文件权限。

“暂停筛选任务”只作用于点击时匹配的主进程任务，保留已传部分；随后新增的任务不受影响。“清除完成记录”只移除匹配的已完成/已取消记录，不删除文件，也保留尚需清理临时文件的记录。可逐项取消或清理；恢复仍需正常的身份和本机文件授权。旧浏览器兼容通道的完整队列与重试继续在对应设备处理，批量动作仅作用于主进程任务。

恢复历史记录时不会用任务刷新抢占正在进行的目录导航，选定的上传路径保持不变。

## 流式传输与校验

任务在选择本机文件前固定目标设备的 SSH 身份，排队后连接配置改变也不会把文件交给另一个主机。

同一管理进程顺序执行文件任务，多个窗口使用同一队列。每个传输块最多 64 KiB，子进程通过继承的文件描述符访问已授权文件；文件内容不会先累计成 Blob 或通过主窗口 IPC 传送。

上传先写远端独占创建的 `.gmssh-transfer-<随机标识>.part`，旁边的元数据关联主机指纹、源内容 SHA-256、大小和目录。续传读取真实远端偏移并核对前缀，完成后重新校验整份远端内容，再以不覆盖目标的 SFTP rename 提交。提交确认丢失时，可用受校验的完成标记识别已有结果。

下载先写使用者选择的目录内的独占临时文件，定期同步到磁盘并记录偏移。恢复时核对远端主机、源文件大小、修改时间、完整 SHA-256 和本机已写部分；完成后重新读取本机文件校验并同步，再以不覆盖已有文件的方式提交，具体策略见下节。记录文件保存提交阶段和文件身份，覆盖“已生成最终文件、任务记录还没更新”这一中断位置。

本机任务记录位于应用用户目录的 `file-transfers/transfer-journal.json`，使用私有目录、文件权限和原子替换。只保存任务元数据、路径和校验摘要，不保存 SSH 密码、桌面密码或本机通道令牌。配置备份不会携带这些任务及临时文件。

## 外接磁盘与网络盘

先使用系统的独占重命名，目标已存在时保留原文件；不支持时尝试原有硬链接路径。两者都不可用的网络盘改为**兼容保存**：独占创建目标，保存其文件身份到任务记录，收到记录确认后才分块写入；同步并完整校验内容后才显示完成。不会退回可能覆盖文件的普通 rename。

兼容保存期间，目标文件名可能已经可见，但内容仍不完整。任务页显示“完成前请勿打开目标文件”，并单独显示保存进度。这条路径需要额外一份文件大小的空闲空间；可暂停、重开并校验已有前缀后继续，不会重新下载已验证的源临时文件。取消仅清理能核对身份的部分文件，达到完整大小的目标保留供继续核验。

部分驱动不支持目录同步时，保留该能力状态；文件内容同步、读取或校验失败仍会停止。断开或只读的磁盘、容量/配额不足和文件系统大小限制分别报告，不自动改存到本机其他目录。

重新挂载可能改变设备号和文件编号。只有重新通过系统窗口确认保存位置后，才允许对变化的目录做内容复核；前缀或完整 SHA-256 不一致时停止。挂载路径改变时可重新选择包含原临时文件的目录；不会复制或删除未授权旧路径中的文件。Node 与 Python 的文件编号统一为无符号 64 位，兼容 SMB 的高位文件 ID。已传完、仅剩本机提交的任务不再要求原 Windows 主机在线。

实现参考 [Apple 的独占重命名接口](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stdio.h)。[Node 的复制接口](https://nodejs.org/download/release/latest-jod/docs/api/fs.html#fscopyfilesrc-dest-mode-callback)不保证原子性，因此兼容复制使用自己的任务记录和校验，并明确显示中间状态。

## 重开后继续

重新打开管理端只读取任务记录；不会根据历史路径自动打开源文件、读临时文件或重新开始传输。未完成任务显示为暂停或待处理。

点击“继续”后先核对现有设备连接；上传重新选择原源文件，下载确认原保存位置。文件身份、源内容或已传部分变化时停止恢复，保留原因。路径权限、磁盘空间或连接恢复后可以继续；源内容已经变化时应取消原任务并重新创建。

取消只清理能核对为本任务所有的临时文件。重开后尚未重新授权的本机临时文件不会被静默删除；需要重新确认原位置。远端离线导致清理失败时保留“清理临时文件”操作和记录，恢复连接后再清理。取消上传不会删除目标完整文件，文件目录本身也不会被递归删除。

## 范围与验证

新版主进程通道单文件上限 1 TiB，最多 2000 项、32 层目录；不跟随符号链接。完整校验会额外读取文件，较大文件在“正在核对”阶段可能需要等待。上限不代表已在所有文件系统和设备上验证这一容量。

本地 APFS 与回环 SMB 挂载已测试；SMB 覆盖兼容保存、暂停、重开及完整下载落盘。exFAT/不支持硬链接和目录同步的行为有模拟回归，但本机拒绝创建测试磁盘映像，尚未完成实体外接盘、其他 NAS 或远程 Windows SMB 服务器验收。

本地使用磁盘 SFTP 替身、真实回环 WebSocket 和 520 MiB 合成文件验证上传、下载、暂停、续传、重开和内容一致性；不据此宣称 Windows 或真实网络验收通过。此轮未操作 A4，也未替换现用 Mac 应用。详见[验证记录](validation.md)。

## Linux 与独立授权

Linux 使用已保存的账号、私钥和跳板机配置，凭据只由主进程传入后台标准输入。首次使用新文件通道时确认 SSH 主机指纹；主机或路由配置变化时停止，不把旧路径自动绑定到新主机。POSIX 根目录、中文及合法的 POSIX 文件名保留，链接不递归跟随。

原生文件工具中已经运行的旧任务留在原窗口；新文件中心启动的 Linux 任务进入统一恢复队列。收藏只包含路径和主机指纹，不保存密码。

独立授权使用服务端的受限文件句柄接口，复用本中心的校验、续传和落盘流程。每次打开通道重新取得服务端当前权限；只看授权不能用直接 IPC 绕过文件限制。参阅[独立授权说明](workspace-and-authorization.md)。
