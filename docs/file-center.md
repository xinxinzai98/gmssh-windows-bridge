# 独立文件中心

0.4.0a16 本地开发候选，对应升级方案第二阶段的第一步：分离文件界面与桌面生命周期。Windows 无需升级服务端；管理端继续复用已经认证的监控 SSH，不要求先连上 RustDesk 桌面。

## 入口与使用

- 点击设备卡片、列表行或详情中的“文件互传”，直接进入该设备的独立文件页。
- 顶部“文件中心”是常驻入口。设备选择器切换设备，分别保留目录位置、文件选择和队列；“全部任务”汇总各设备的近期任务，点击“查看任务”回到对应设备处理。
- Windows 桌面工具栏中的“文件互传”也进入同一个中心。旧管理页面没有接入该入口时，保留原有文件侧栏作为兼容回退。
- Linux 继续使用 GMSSH 原生文件管理。“文件中心”提供原生入口并说明范围，其任务暂不计入本中心的 Windows 队列。

如果提示先连接监控，正常连接该设备的监控 SSH 后再刷新目录；文件中心不会反复提交账号密码，也不会自动安装远端组件。

## 任务与连接

同一管理窗口中的 Windows 文件任务按顺序取得传输许可。正在传输、等待许可、失败与完成分别显示；不同设备的目录和任务不串用。文件页将未完成任务状态报告给主进程，确认后才开始远端读写。

收起文件中心、回首页、切换设备和关闭桌面标签均保留文件页与队列。文件传输持有自己的 SSH 使用权；任务完成或取消后关闭自己的文件通道，目录读取结束也释放浏览通道，不提前关闭桌面或终端。

可取消当前任务、重试失败或已取消的任务；上传同名冲突时可改名重试。文件夹上传、多选、拖入、进度和文件夹 ZIP 下载继续保留。任务总览最多显示每台设备 100 项摘要和合计 200 行，完整队列在设备页查看。

退出或关闭管理窗口时，存在未完成任务会默认选择“继续传输”。明确选择“停止传输并退出”才取消并退出；渲染页面无响应时，退出保护的等待有时间上限。地址或本机通道发生变化时保留旧页及任务摘要，不把等待中的任务自动交给新的端点；核对后显式更新文件通道，失败文件需要重新选择。

## 当前边界与后续步骤

本阶段队列保存在管理窗口内。退出、重新载入管理窗口或文件页后，未完成任务需要重新选择文件；没有自动任务恢复和断点续传。取消后仍在同一窗口保留的本机 File 对象可以用于重试，完成任务会释放该引用。

单文件及文件夹 ZIP 仍限 512 MiB。下载仍在浏览器中累计 Blob，再交给本机保存；“完成”代表已接收并交给浏览器保存，不代表已经核实本机磁盘落盘。因此本阶段没有放宽文件大小，也不宣称内存与文件大小无关。

下一步继续第二阶段的流式落盘与恢复：由使用者授予本机文件句柄，传输使用临时文件和校验，记录已确认偏移，恢复前核对设备身份与源文件，管理端重开后先展示待恢复任务并重新取得所需文件授权。

本地验证使用两个回环 WebSocket 服务、模拟 SFTP 存储和合成文件。Windows 原生、Linux 原生文件工具及实际管理端界面仍需后续实机验收，本轮不操作 A4。
