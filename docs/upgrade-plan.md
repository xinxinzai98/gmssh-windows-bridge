# GMSSH Windows Bridge 升级方案

方案初稿：2026-10-16；状态核对：2026-10-22。当前候选为 0.4.0a38，公开安装包仍为 0.4.0a8 Alpha。下文保留四阶段的设计和完成标准，当前交付状态以[候选说明](release-0.4.0a38.md)及[验证记录](validation.md)为准。

实施进度：四阶段的本地实现均已覆盖：连接诊断与只读工具、Windows/Linux 独立文件中心、工作区与历史、独立授权及服务端权限。后续 CLI/MCP、文件恢复、窗口焦点、可选系统解锁和超时恢复也已加入；各阶段本地回归与实机结果分别记录。

已有设备的升级、重启恢复、改密重连、保留模式卸载重装、CLI/MCP 中文输入保存、独立文件授权降级与撤销、520 MiB 文件恢复以及 Mac 客户端重开已有实机记录。0.4.0a37 实测自然超时后自动恢复，但偶发传输长停顿根因未确认，不能列为连续零掉线通过。纯净系统完整首装、原生 ConPTY 及未逐项执行的边界保持待验；本轮只整理通用候选，不替换日常应用或部署设备。

升级方向是本地直连的综合设备管理端，配合一体化 Windows 服务端。围绕同一台电脑组织监控、桌面、终端、文件和维护工具，先解决连接故障难定位、维护需要切换多个窗口、传输任务依附桌面等问题。

实施顺序为：**连接诊断与只读系统工具箱 → 独立文件中心 → 工作区与连接历史 → 服务端会话控制及权限**。各阶段先完成代码和本地回归，再安排对应实机验收；本方案不启动设备部署或实机操作。

## 产品边界

- Mac 保留 GMSSH 原生加号、Linux 添加流程、列表与卡片切换，以及现有首页和顶部设备标签。两端沿用同一品牌、颜色、图标和动作名称。
- Windows 继续提供一个 GMSSH 安装入口、后台服务和托盘。内部复用桌面引擎，日常使用不需要打开 RustDesk 原界面。
- 默认面向局域网，直接使用提供的 IPv4 或 IPv6 地址。不内置 Tailscale，不管理地址分配、DDNS、路由或打洞。
- 长效连接码、普通连接文件、二维码和手动填写共同保留。二维码承载普通连接码或 JSON 文本，通用扫码工具读出的文字可以粘贴到同一接入入口。
- 保留管理员日常连接所需的完整操作能力。后续新增只看或受限模式时，必须由服务端实际限制对应能力。
- 本轮不扩展企业组织架构、云账号体系、软件批量分发、补丁管理或自动录屏。

## 第一阶段 连接诊断与只读系统工具箱

### 连接诊断

从卡片更多菜单和设备详情进入“连接诊断”。每项显示未检查、进行中、通过、失败或不支持，并附采样时间。SSH、桌面、文件三个通道分别记录状态。

1. 核对所选设备、提供的地址、端口和已保存主机身份。
2. 检查目标 SSH 端口可达性，区分超时、拒绝连接和地址错误。
3. 记录正常连接过程的认证结果；健康检查不反复尝试账号密码。
4. 检查监控采集和文件通道是否可用。
5. 检查桌面握手、首帧和后续帧接收；SSH 可用不代表桌面已经连接。

SSH TCP 延迟、接收帧率、接收带宽分别标注测量对象。不能测得的端到端画面延迟不显示估算的“真实延迟”。诊断页可导出脱敏报告，默认只包含版本、阶段、错误码和时间；不包含凭据、连接码、密钥、会话令牌或完整日志正文。

版本信息增加管理端、本机兼容桥、Windows 服务端和桌面引擎版本。能力信息通过现有已认证通道读取，不新增公网监听端口。旧服务端未提供某项能力时显示“版本未知”或“需要更新”，已有桌面、终端和文件入口继续按原方式工作。

### 只读系统工具

| 工具 | Windows | Linux | 共同要求 |
|---|---|---|---|
| 进程 | 进程名、PID、内存、CPU 采样 | 从现有进程数量扩展到列表 | 说明 CPU 采样周期与内存口径，可搜索和排序 |
| 服务 | Windows 服务状态与启动方式 | 检测可用的服务管理方式 | 不支持时说明原因；第一阶段不执行启停 |
| 日志 | 系统及应用事件摘要 | 可用的系统日志摘要 | 默认限制时间范围和条数，正文按需读取 |
| 存储与网络 | 磁盘、空间、网卡和链路 | 分区、空间、网卡和链路 | 保留单位、更新时间，按实际权限返回结果 |

查询沿用固定命令和受限操作类型，界面只提交允许的筛选条件。查看权限不足时报告受限项，不自动提升账号权限。终端中的用户命令与系统工具查询保持各自入口。

### 完成标准

- 覆盖离线、端口不可达、主机身份变化、认证失败、SSH 正常但桌面失败、首帧超时、采集拒绝和旧版本八类场景。
- 每种失败定位到具体阶段，保留此前有效信息，不把旧数据当作新采样。
- 故障重试不重复提交密码，不自动替换已保存的主机密钥。
- Windows 和 Linux 均完成至少一种进程、服务及日志查询；不可用项有明确说明。
- 工具查询不写远端文件、不改变服务状态；Linux 原生添加、终端和文件入口回归通过。

## 第二阶段 独立文件中心与断点恢复

分两步实施，先调整任务生命周期，再改变传输协议。

### 文件中心

- 从设备卡片直接进入文件工具，不要求先建立桌面画面。
- 同一设备的桌面、终端和文件共用已核验身份，各自持有连接使用权。任务完成或取消后释放文件通道，不提前关闭其他会话。
- 任务由管理端统一维护，关闭文件面板或桌面标签不终止任务。退出管理端时明确处理未完成任务。
- 保留当前多选、文件夹、进度、取消、重试和同名改名；先保持可控的顺序传输，不同时增加无限并发。

### 流式传输与恢复

0.4.0a16 下载将分块累计为内存中的 Blob；0.4.0a17 的独立中心已改为有权限约束的流式落盘，新通道上限提升至 1 TiB，旧兼容路径保留 512 MiB。本机文件由用户选择，管理端通过受限文件句柄访问，不让网页请求任意本机路径。

上传和下载都先写临时文件，成功校验后再提交目标文件。恢复记录关联已核验设备、源与目标、大小、修改时间、已确认偏移及必要的内容摘要；源文件变化或身份不匹配时停止续传。同名目标继续采用明确选择，不静默覆盖。

管理端重启后先展示待恢复任务。本机源或目标需要重新授权时，由用户重新选择并核对，不能仅凭上次保存的路径后台继续读取。目录与临时文件权限不足时保留原因和失败项，不伪报完成。

### 完成标准

- 桌面标签关闭后，文件任务仍能运行，其他设备的任务互不串用。
- 取消只影响当前传输，不关闭同设备的桌面和终端。
- 使用超过现有限制的合成文件验证流式传输，并检查内存不会随文件体积线性增长。
- 覆盖断网、管理端退出、磁盘满、权限不足、源文件改变、同名冲突和中文路径。
- 完整传输与恢复后均比对内容摘要；失败项不覆盖已有完整文件，部分文件与完成文件有明确区分。

## 第三阶段 工作区布局与连接历史

每台设备保留一个清晰的工作区。先让概览、桌面、终端和文件的切换保持同一设备，再加入桌面与终端并排显示。记录该设备的屏幕选择、缩放和画质偏好，以及本机工作区布局；首次恢复时核对当前显示器和窗口尺寸。

重新打开管理端时，可以恢复标签和布局。连接恢复使用当前有效认证；认证失败停止自动重试并提示更新，不从历史中找回旧密码。重复点击桌面入口复用现有会话，断开、关闭标签和退出程序有各自明确含义。

连接历史保存在本机，只记录设备、通道、开始与结束时间、结果、时长和断开原因。显示进行中的会话，可按设备筛选并配置保留时间。终端命令、键盘输入、剪贴板和屏幕内容不进入此历史记录。

### 完成标准

- 多台设备切换、分屏和布局恢复后，键鼠、终端与文件动作都指向正确设备。
- 恢复标签不会创建重复桌面或重复本机监听。
- 缩放和画质按设备保存，显示器变化时有合理回退。
- 历史中的活动状态与真实会话生命周期一致；异常退出后不永久显示仍在连接。
- 历史导出和设备配置备份各自保持明确内容范围。

## 第四阶段 服务端会话控制与权限

Windows 托盘显示可核验的当前连接信息和连接时间，提供“断开本次桌面”等具体动作。断开单个会话不等同于停止 Windows 后台服务，也不影响无关程序的服务。

权限按桌面查看、键鼠、剪贴板、文件、终端和电源分别表达。只看模式必须在服务端约束相应操作；仅禁用管理端按钮不能视为权限控制。管理员常用连接保持完整能力，受限模式作为可选接入方式。

按管理端单独撤销授权需要独立凭据和服务端认证支持，作为本阶段单独的协议任务。现有共享密码模式下，重置连接码只阻止旧码继续接入，不能撤销已保存 SSH 密码的管理端；界面须继续如实说明。

### 完成标准

- Windows 会话列表与实际连接一致，单会话断开不误停系统服务。
- 从直接请求接口的测试中验证权限限制，覆盖键鼠、终端、文件和电源，不能只检查按钮状态。
- 长效连接码与手动接入保留，旧设备不因新增权限字段失去基本连接能力。
- 独立凭据尚未完成时，不提供名称为“撤销此管理端”但实际上无效的操作。

## 交付与实施顺序

| 顺序 | 交付范围 | 进入下一步的条件 |
|---|---|---|
| 0 | 固定 0.4.0a14 基线，保留候选与已记录验证结果 | 能复现构建，源码和附件对应，已有连接不受新开发影响 |
| 1 | 诊断、版本能力、进程／服务／日志只读面板 | 第一阶段完成标准通过，旧版兼容和 Linux 原生回归通过 |
| 2 | 独立文件中心，再实现流式传输与恢复 | 两步分别交付，内容校验、取消和失败恢复通过 |
| 3 | 同设备工作区、布局记忆、连接历史 | 设备隔离、生命周期和恢复行为通过 |
| 4 | Windows 活动会话、服务端权限和独立凭据 | 按功能完成协议与原生检查后，逐项安排实机验收 |

每一步都产出对应源码、变更说明、可复现检查和验证记录。候选版本号随实际完成范围确定，不把拟定阶段写成已发布功能。升级沿用已有文件备份与回退机制，不重置用户账号、密码、主机身份或现有设备目录。

实机验收和公开发布分别安排：已经完成的设备项目保留其版本与范围，不重复列为“尚未开始”；剩余项目逐项核对原生界面、纯净首装与跨设备边界。测试环境与部署影响需明确后执行，模拟检查不代替设备结果。
