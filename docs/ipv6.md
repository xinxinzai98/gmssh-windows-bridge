# 使用提供的 IPv6 地址

适用于 0.4.0a25 源码候选；IPv6 支持从 0.4.0a11 开始。地址由使用者或外部系统提供，增强端按该地址直接连接。地址配置、静态 / 动态变化、DDNS、自动发现、NAT 穿透和中继均不属于此功能。

Windows 服务端现在从所有网卡实时读取 IPv4 / IPv6。复制普通连接信息、长效连接码、二维码和新建独立授权均携带当前可用的地址；包括公网、ULA 和临时 IPv6，仍在有效期内的 Deprecated 地址也保留。回环、`fe80::` 链路本地、多播、未完成地址检测或冲突地址不作为连接目标。链路本地地址中的网卡编号属于服务端，不能直接用于管理端。

## 允许 ping

在 Windows 管理面板底部或托盘菜单点击“允许 ping”，完成正常管理员提示后，启用本程序的 IPv4 Echo Request（类型 8）与 IPv6 Echo Request（类型 128）入站规则。允许来自任意来源的这两种回显请求，用于连接诊断；不开放 TCP / UDP 或其他 ICMP 类型。规则使用 [Windows NetSecurity](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule) 配置。

再次点击“关闭 ping”只停用 `GMSSH-Windows-Ping-IPv4`、`GMSSH-Windows-Ping-IPv6` 两条规则；已有系统或其他软件的规则保留。安装和升级不会自动开启 ping。状态显示的是本程序规则，系统阻止规则、组策略、路由器或对端网络仍可能使 ping 无响应。ping 开关也不改变 SSH 或连接码的访问范围。

## 接入和修改地址

1. Mac 首页点击左侧加号 →“添加机器”→“Windows”。可以粘贴现有长效连接码、选择公开连接文件，或点击“手动填写”。
   连接码和独立授权码默认勾选“自动选择连接码中的可用地址”，会优先保留可达的原连接，再并行尝试码内的地址，逐一核对主机身份。探测不发送密码或接入凭证；选定地址后才执行正常认证。未找到可用地址时可以从列表指定 IPv6 重试。填写地址会取消自动选址，保留明确选择；手动和普通连接文件流程继续保留。
2. 填写 IPv6 和 SSH 端口。`2001:db8::42` 是纯地址；`[2001:db8::42]:2222` 含端口；裸地址末尾的数字始终属于 IPv6，不猜作端口。地址在保存时规范化。本文使用文档示例地址，实际使用时换成目标地址。
3. 手动方式先核对 Ed25519 SSH 指纹，再输入当前连接密码。只有确定 Windows 两种连接共用密码时才勾选共享密码；独立 RustDesk 安装保留其桌面认证。
4. 已接入设备右键“编辑连接地址”，填入新地址，点击“更新地址并重连”。新地址须呈现原 SSH 公钥并通过当前密码认证。保留原机器 ID、本机端口和桥主机密钥；服务启动、GMSSH 回读或配置保存失败时恢复原记录。

连接文件 schema 仍为 1，`addresses` 可混合 IPv4 和 IPv6；旧 IPv4 文件继续可用。连接码协议仍为 `GMSSH-CONNECT1`，证书与 SSH 设备身份绑定，填入新地址也不会跳过身份检查。更换 SSH 账号或 SSH 端口会改变身份，需要重新核对和接入。

监控、PowerShell 和 SFTP 使用同一 SSH 目标；桌面引擎继续只通过 SSH 的固定 `127.0.0.1:21118` 通道访问。浏览器查看器仍在 Mac 本机回环地址，不把 Windows 的桌面端口直接暴露到公网。IPv6 不改变文件权限和管理员 / UAC 行为。唤醒仍依赖原局域网 IPv4 广播配置。

## 网络访问范围

使用前，控制端须能到达所提供的 IPv6 和 SSH 端口；系统及上游防火墙须已允许相应来源。程序不代为配置路由或扩大防火墙授权。只使用手动 / 连接文件方式时不依赖连接码的 HTTPS 端口。

长效连接码额外使用 TCP 22257。连接码服务使用双栈监听；安装器继续创建绑定本程序的 `LocalSubnet` 规则。0.4.0a25 同时识别本机正在启用网卡的 IPv6 前缀，因此同一局域网中的公网 IPv6 可以按原局域网规则接入。连接码内的地址不会被当作管理端来源授权。

跨网段接入时，在 Windows 管理面板底部或托盘菜单点击“IPv6 接入”，完成正常管理员提示。每行填一个**管理端来源**的 IPv6 或 CIDR（不是 Windows 的目标地址），点击“保存来源范围”。界面同步接入服务策略和本程序的两条专用入站规则：TCP 22257 绑定接入服务程序，TCP 22 绑定已核对的 SSH 服务程序。每次操作保留安装记录备份；发生部分失败时恢复原策略及规则。来源范围最多 32 条，不接受 IPv4、回环、链路本地、多播或 `::/0`。

清空并保存会移除这两条额外规则，保留原局域网规则。已建立的 SSH 会话需单独断开；独立授权可在“会话与授权”中撤销。安装和升级不会默认开放跨网段来源，也不会修改路由器或地址分配。公网可达性还取决于控制端、目标电脑和上游网络。

旧版服务端仍可通过受限的 `agent.json` 配置来源；以下是兼容字段示例。新版优先使用上述界面以同时配置需要的程序防火墙规则：

```json
{"connectIpv6Sources":["2001:db8:10::5","2001:db8:20::/64"]}
```

只填确实获准接入的来源。直接修改此字段不会修改 Windows 防火墙；跨子网规则需要另外核对。不要覆盖 `agent.json` 其他字段或公开上传该文件。

新版明确区分“来源未获准”和“连接码失效”：前者到服务端“IPv6 接入”中配置，后者重新复制有效的码。旧版只返回通用拒绝时，管理端同时提示检查来源和连接码，不直接判定密码错误。

Windows 已有连接信息可交给管理端，再直接填写提供的 IPv6。需要生成指定地址的连接码时，受管理安装中的 `Get-GMSSHConnectCode` 也支持显式 `-Address` 参数；它只替换本次导出的地址，不改网卡、账号或密码。常规托盘复制行为保留。

## 已验证范围

0.4.0a25 已在既有 Windows 11 安装和 Apple Silicon Mac 上完成同网段实测：仅含一个公网 IPv6 的长效连接码可自动核对地址、认证并更新原卡片；保留原名称、机器 ID、端口及设备总数，实际监控和 1920×1080 桌面恢复。Mac 正常退出重开后，自动使用已保存凭据恢复同一 IPv6 桌面。未更改密码、重启 Windows 或新增跨网段入站规则。这不能代表跨互联网可达或全新系统安装已通过；详情见[验证记录](validation.md)。

本机 `::1` 的真实 SSH 协议测试覆盖固定主机密钥认证、监控采集通道、终端输入、SFTP 往返和固定桌面隧道；合成设备测试覆盖原卡片迁移、启动 / 认证 / 保存失败回退和旧钥匙串兼容。HTTPS 测试覆盖双栈监听、原设备证书和显式来源策略。上述使用合成账号、数据和桌面字节，未证明真实公网 Windows 画面、跨网段可达或硬件唤醒。
