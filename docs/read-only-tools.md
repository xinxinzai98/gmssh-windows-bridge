# 连接诊断与只读系统工具

0.4.0a15 本地开发候选。入口在设备卡片或列表行的“更多操作”中，也在设备详情区提供“连接诊断”和“系统工具”。保留原来的桌面、终端、文件互传及电源入口。

## 使用

1. 正常连接所选设备的监控。Windows 工具复用已认证的 SSH；Linux 工具复用该设备已打开的 GMSSH 原生桌面会话。如果没有可用会话，面板会提示先连接，再点刷新。
2. 打开“连接诊断”，或在“系统工具”中选择进程、服务、日志。读取由使用者点击触发，不进行后台定时查询。搜索后点击“查询”或回车；排序、条数和日志范围变化会触发一次读取。
3. 日志列表只显示摘要，点击“详情”后才读取该条正文。正文最多显示 4096 个字符；记录已轮转、权限不足和查询成功但没有记录分别显示。

查询不终止进程、不启停服务、不修改日志或系统设置，也不会自动安装组件、提权或反复验证密码。诊断导出保留版本、阶段、状态码和时间，排除设备名、地址、账号、密钥、密码、连接码、会话令牌和日志正文。

## 显示口径与兼容性

| 项目 | Windows | Linux |
|---|---|---|
| 进程 | `Get-Process`，约 1 秒 CPU 差值除以逻辑处理器数；内存为工作集 | `ps` 的进程生存期 CPU 平均值，可超过 100%；内存为 RSS |
| 服务 | `Win32_Service` 的状态、说明和启动方式 | 检测 `systemctl` 并读取 systemd 服务；启动方式未查询，显示 — |
| 日志 | 固定的 System、Application 事件源 | `journalctl` 当前账号可读的记录；不支持时说明原因 |
| 范围 | 50、100、200 条；日志最近 1、6、24 小时 | 相同；进程和服务先限制最多 4096 项再搜索、排序 |

无法读取的字段显示 —。刷新失败保留上次成功采样，并明确显示原时间及“不代表当前筛选结果”。读取权限不会自动改变。

诊断分别显示目标配置、SSH TCP 建连、主机身份、认证、监控、SFTP、桌面通道、RustDesk 握手、桌面认证、首帧及画面接收。通道打开不表示已收到 RustDesk 握手；桌面认证通过也不表示已有画面。认证后 15 秒未收到首帧会在诊断中显示超时，迟到的首帧可以恢复该项。

TCP 延迟只代表 SSH 端口建连耗时。平均解码帧率和 WebSocket 接收负载速率从本次桌面连接启动时累计，不作为端到端画面延迟；静止桌面可能不产生新帧。重新连接会重置计数；断开后保留接收记录并显示断开状态。

管理端与本机桥版本来自运行代码；Windows 服务端版本来自固定安装状态文件，桌面引擎版本来自文件元数据或已验证的协议握手。旧安装不提供版本时显示“未知”。Linux 原生接口没有暴露独立的 SSH 主机密钥、SFTP 和桌面画面探测结果，这些阶段明确显示未检查或不支持，不用一次 SDK 查询代替全部通道验收。

Linux 命令只在当前设备的既有原生 webview 中执行；不调用原生安装、添加、登录测试等接口。没有 `systemctl` / `journalctl` 的发行版保留原桌面、终端、文件功能，本版工具显示不支持。

## 实现与验证边界

- 界面仅发送设备 ID、固定查询名和受限筛选选项；主进程核对本机页面和保存的设备配置，剔除账号凭据后返回公开上下文。
- Windows 从本机受保护操作通道借用已有 SSH，固定脚本通过标准输入执行，不向远端落地文件；默认 Windows 命令行只承载简短引导命令。
- Linux 使用固定命令模板，搜索只在本机过滤。日志详情使用校验后的数字记录 ID 或 journal 游标，不接受任意命令、路径、服务名操作或任意事件源。
- 单次查询限制输出 256 KiB、最长等待约 27 秒；单个窗口同一时刻只执行一项查询。关闭或换设备后丢弃迟到结果。
- 界面使用文本节点显示日志；导出报告采用字段及状态码白名单，不复制完整返回对象。

本地回归包含合成会话、回环 WebSocket/TCP、受控 Linux 命令替身和浏览器界面检查。Windows 原生命令、Linux 实机、旧版实际 GMSSH webview 的端到端查询仍需单独验收。本轮按要求不连接或部署 A4，不替换正在使用的 Mac 应用。

日志游标与条数行为参照 [systemd 的 journalctl 源文档](https://github.com/systemd/systemd/blob/main/man/journalctl.xml)。本实现不使用会写游标文件的选项。
