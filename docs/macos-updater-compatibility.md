# a38 更新器兼容修复

此文记录 a40 的更新器兼容范围与验收步骤。已发布 `v0.4.0a39` 的 ZIP/wheel 不包含这些修复；a40 使用新的发布文件，实际原生验收结果见 a40 Release。

## 支持范围与处理方式

| 当前应用标识 | 更新前版本 | 处理方式 |
| --- | --- | --- |
| `local.gmssh.windows.launcher` | `0.4.0a38` | 在现有位置更新，保留标准标识 |
| `local.gmssh.windows.launcher.preview.unlock225` | `0.4.0a38` | 在现有位置更新，保留该已知预览标识 |

仅精确接纳这两个标识，不按 `preview.*` 前缀放行。无需改写 `CFBundleIdentifier`、重建 App 或迁移权限；`CFBundleName`、主程序 UUID、ASAR 中的配置字节、独立 Python 路径、原版资源和钥匙串路径继续沿用。错误信息分别报告不支持的版本和不支持的应用标识。

两种标识共用前置检查：应用必须已退出，签名与增强 ASAR 完整性必须有效，主程序必须含受支持的 UUID，运行环境必须独立且属于当前账号，包及版本元数据必须完整并与应用版本一致。标识匹配不会跳过这些检查。签名后再次核对应用标识、helper 名称、UUID 和配置；失败沿用备份恢复，不把预览版改名成标准版。

回退继续从核验过的备份读取应用元数据和配置，因此当前新包或签名不完整时仍可进入恢复流程。没有改动恢复记录的路径比较；本次 `/var` 与 `/private/var` 不一致修复位于测试夹具的 `.resolve()`，不据此宣称真实回退有故障。

## 云端验证与 Mac 待验

云端只运行合成应用文件、模拟签名调用及临时独立目录。更新器测试覆盖两种标识的前置检查、原位更新、签名失败恢复、签名后标识异常恢复、损坏备份拒绝、当前签名／包中断后的恢复和显式 CLI 回退。另用符号链接构造临时目录别名：原夹具可复现路径不一致，规范化后的夹具应通过。Linux 上的别名测试不能记为默认 macOS 路径测试已经通过。

在 Mac 本机仓库中使用已准备的测试 Python，保留终端原有默认临时目录设置，不设 `TMPDIR=/private/tmp` 绕开路径问题：

```bash
python -c 'import tempfile; from pathlib import Path; p = Path(tempfile.gettempdir()); print(p, "=>", p.resolve())'
python -m unittest discover -s tests -p test_macos_update.py -v
```

之后分别对标准 a38 和上述已知预览 a38 执行更新包的 `--check`，核对其识别的标识；再按本机授权验证真实签名、升级后的界面、配置及 UUID 保留、失败恢复和显式回退。更新器不会自动连接设备。只把实际执行的本机步骤记录为完成，保留未执行范围；不把模拟结果写为真实安装验收。

GitHub 的 macOS Python 矩阵已包含更新器测试；账户计费锁定导致 job 未启动时，没有产生 macOS 测试结果。需由账户侧解除限制后重跑修复提交的 workflow，检查实际步骤和结果。工作区通过、待执行和 GitHub CI 通过须分别记录。
